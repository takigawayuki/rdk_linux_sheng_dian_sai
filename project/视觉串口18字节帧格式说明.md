# 视觉到摆杆控制器：18 字节串口帧格式说明

本文档供下位机开发人员实现 UART DMA 接收、CRC 校验和滚球状态解析。协议实现位于：

```text
Driver/vision_protocol.py
Driver/my_serial.py
Tools/run_vision_serial.py
```

## 1. 串口参数与发送频率

```text
波特率：115200 bit/s
数据位：8
停止位：1
校验位：无
流控：无
字节序：小端序
发送时机：视觉每处理完一帧后发送一包
包长：固定 18 字节
```

在 120 包/秒时，线路占用约为：

```text
18 字节/包 × 10 bit/字节 × 120 包/秒 = 21600 bit/s
```

因此 `115200 bit/s` 带宽足够。USB-TTL 与控制板必须共地，USB-TTL 的 TX 接控制板 RX。确认双方 IO 电平后再连接，不要默认把 USB-TTL 的 5 V 电源脚连接到控制板。

## 2. 18 字节帧定义

| 字节偏移 | 长度 | 类型 | 名称 | 说明 |
| --- | ---: | --- | --- | --- |
| 0 | 1 | `uint8_t` | `sof` | 固定起始符 `0xA5` |
| 1 | 1 | `uint8_t` | `status` | 视觉状态，见第 3 节 |
| 2～5 | 4 | `float32` | `error_cm` | 位置偏差，`目标位置 - 实测位置`，单位 cm |
| 6～9 | 4 | `float32` | `position_cm` | 钢球相对中心 O 的实测位置，单位 cm |
| 10～13 | 4 | `float32` | `velocity_cm_s` | 钢球沿摆杆的速度，单位 cm/s |
| 14～15 | 2 | `uint16_t` | `sequence` | 视觉帧序号，65535 后回到 0 |
| 16～17 | 2 | `uint16_t` | `crc16` | 前 16 字节的 CRC，低字节先发送 |

所有 `float32` 都采用 IEEE 754 单精度、小端序，必须确认下位机编译器中 `sizeof(float) == 4`。

## 3. 状态字节

| 值 | 名称 | 含义 | 下位机建议 |
| ---: | --- | --- | --- |
| `0x00` | `LOST` | 当前没有可信钢球位置 | 停止位置环积分，进入约定的安全姿态 |
| `0x20` | `DETECTED` | 当前帧真实检测到钢球 | 正常使用位置、偏差和速度 |
| `0x21` | `PREDICTED` | 短遮挡预测，最长约 0.12 s | 可以短时控制，但不要长期积分 |

兼容参考协议的判断方式：

```c
bool vision_valid = (status & 0x20U) != 0U;
bool vision_predicted = (status & 0x01U) != 0U;
```

当状态为 `LOST` 时，上位机会把三个 float 字段全部置零。但是下位机必须以 `status` 为准，不能因为 `error_cm == 0` 就认为钢球正好位于目标位置。

## 4. 坐标和误差正方向

```text
中心 O：0 cm
画面右侧：正位置
画面左侧：负位置

error_cm = target_position_cm - position_cm
```

当前统一坐标约定为：从相机画面观察，小球向右为正，向左为负；向右运动时 `velocity_cm_s > 0`。视觉入口默认对标定映射结果乘 `BALL_VISION_DIRECTION = -1.0`，位置和速度必须一起换向，之后再计算 `error_cm`。

中心目标下：

```text
小球在右侧：position_cm > 0，error_cm < 0
小球在左侧：position_cm < 0，error_cm > 0
```

示例：目标为 `+1 cm`，钢球实测为 `+3 cm`：

```text
error_cm = +1 - (+3) = -2 cm
```

协议只规定钢球坐标和误差符号。步进电机“正转”到底让钢球向左还是向右，必须在真机低速测试中确定，并在下位机中设置一次方向系数。不要为了匹配电机接线而修改视觉坐标定义。

## 5. CRC16 参数

本协议使用与给定示例一致的 CRC：

```text
算法：CRC-16/MCRF4XX 形式
初始值：0xFFFF
反射多项式：0x8408
输入：buffer[0] 到 buffer[15]，共 16 字节
最终异或：无
发送顺序：CRC 低字节在 buffer[16]，高字节在 buffer[17]
```

给定参考数据的前 16 字节：

```text
A5 20 00 80 0F 43 CD CC B6 43 00 00 00 00 00 00
```

计算结果为 `0x99BE`，所以发送顺序是：

```text
buffer[16] = 0xBE
buffer[17] = 0x99
```

## 6. 下位机 C 参考代码

```c
#include <stdbool.h>
#include <stdint.h>
#include <string.h>

#define VISION_FRAME_SIZE 18U
#define VISION_PAYLOAD_SIZE 16U
#define VISION_SOF 0xA5U
#define VISION_STATUS_LOST 0x00U
#define VISION_STATUS_DETECTED 0x20U
#define VISION_STATUS_PREDICTED 0x21U

typedef struct {
    uint8_t status;
    float error_cm;
    float position_cm;
    float velocity_cm_s;
    uint16_t sequence;
    bool valid;
    bool predicted;
} VisionState;

static uint16_t vision_crc16(const uint8_t *data, uint16_t length)
{
    uint16_t crc = 0xFFFFU;
    for (uint16_t i = 0U; i < length; ++i) {
        crc ^= data[i];
        for (uint8_t bit = 0U; bit < 8U; ++bit) {
            if ((crc & 0x0001U) != 0U) {
                crc = (uint16_t)((crc >> 1U) ^ 0x8408U);
            } else {
                crc >>= 1U;
            }
        }
    }
    return crc;
}

bool vision_decode(const uint8_t frame[VISION_FRAME_SIZE], VisionState *state)
{
    if (frame == NULL || state == NULL || frame[0] != VISION_SOF) {
        return false;
    }

    const uint16_t received_crc =
        (uint16_t)frame[16] | ((uint16_t)frame[17] << 8U);
    if (vision_crc16(frame, VISION_PAYLOAD_SIZE) != received_crc) {
        return false;
    }

    if (frame[1] != VISION_STATUS_LOST &&
        frame[1] != VISION_STATUS_DETECTED &&
        frame[1] != VISION_STATUS_PREDICTED) {
        return false;
    }

    state->status = frame[1];
    memcpy(&state->error_cm, &frame[2], sizeof(float));
    memcpy(&state->position_cm, &frame[6], sizeof(float));
    memcpy(&state->velocity_cm_s, &frame[10], sizeof(float));
    state->sequence =
        (uint16_t)frame[14] | ((uint16_t)frame[15] << 8U);
    state->valid = (state->status & 0x20U) != 0U;
    state->predicted = (state->status & 0x01U) != 0U;
    return true;
}
```

不要直接把接收缓冲区强制转换为 C 结构体指针，结构体对齐可能改变字段偏移。上面的 `memcpy` 写法不依赖结构体是否压缩对齐。

## 7. 固定联调测试帧

以下状态：

```text
status = DETECTED
error_cm = -2.0
position_cm = +3.0
velocity_cm_s = -2.0
sequence = 9
```

对应完整 18 字节：

```text
A5 20 00 00 00 C0 00 00 40 40 00 00 00 C0 09 00 82 F4
```

下位机应解析出上述数值，并验证 CRC 为 `0xF482`，串口顺序为 `82 F4`。

## 8. DMA 接收与安全要求

1. 推荐 DMA 循环缓冲或 Receive-to-Idle，不要假设一次中断一定正好收到 18 字节。
2. 在字节流中先寻找 `0xA5`，凑满 18 字节后再校验 CRC；CRC 失败则向后继续寻找下一个 `0xA5`。
3. 只有 CRC 正确、状态合法时才更新全局 `VisionState`。
4. 使用本地接收时间实现通信超时。建议超过 `50 ms` 没有收到新有效包就按 LOST 处理。
5. 用 `sequence` 检查重复包、跳帧和链路停滞；序号回绕属于正常行为。
6. 下位机 PID 不应在 LOST 状态继续累计积分，否则钢球重新出现时容易产生突跳。
7. 第一次带电联调应抬起机构或限制步进电机速度和角度，先确认误差正负方向，再闭环控制钢球。

## 9. 上位机运行命令

### 9.1 不连接串口，先核对固定帧

```bash
python3 -m project.Tools.send_vision_packet \
  --status detected \
  --error-cm -2 \
  --position-cm 3 \
  --velocity-cm-s -2 \
  --sequence 9 \
  --print-only
```

输出必须是第 7 节的固定测试帧。

### 9.2 只向下位机发送一包固定数据

第一次测试应断开电机动力或禁止控制输出：

```bash
python3 -m project.Tools.send_vision_packet \
  --serial-port /dev/ttyS1 \
  --status detected \
  --error-cm -2 \
  --position-cm 3 \
  --velocity-cm-s -2 \
  --sequence 9
```

确认下位机得到 `-2、+3、-2、9` 且 CRC 正确，再测试连续视觉。

### 9.3 运行实时视觉和连续发送

目标位置为中心 O 点：

```bash
python3 -m project.Tools.run_vision_serial \
  --device /dev/video0 \
  --serial-port /dev/ttyS1 \
  --baudrate 115200 \
  --target-cm 0 \
  --preview-fps 30 \
  --log-interval 0.5
```

窗口中按 `q` 退出。无显示器运行时添加 `--headless`，此时使用 `Ctrl+C` 停止。

该入口会在每次图像处理完成后发送一包。预测窗口优化后的现有视频离线处理速度约为 123.8 FPS，但最近一次真机完整通路实测仍只有 23.7 Hz；实际运行日志会打印相机、视觉、串口和预览的分段耗时。帧序号和接收超时必须按真实到包时间处理，不能在下位机中写死 8.33 ms。

## 10. 使用 PC 串口助手进行双向测试

### 10.1 接线与串口助手设置

RDK 和 PC 必须是串口链路的两个独立端点，不能让两个程序同时打开同一个 `/dev/ttyS1` 或 COM 口。当前目标板 UART1 按 `/dev/ttyS1` 使用；只有使用插在 RDK USB 口上的 USB-TTL 时才通常是 `/dev/ttyUSB0`。

```text
RDK TX  -> PC USB-TTL RX
RDK RX  <- PC USB-TTL TX
RDK GND -- PC USB-TTL GND
```

若两端各使用一个 USB-TTL，则两个模块的 TX/RX 交叉、GND 相连。不要连接两个模块的 VCC。

PC 串口助手设置：

```text
波特率：115200
数据位：8
停止位：1
校验位：None
流控：None
```

### 10.2 第一步：ASCII/任意字节回显测试

先在 PC 串口助手中打开对应 COM 口，再在 RDK 运行：

```bash
python3 -m project.Tools.serial_duplex_test \
  --serial-port /dev/ttyS1 \
  --baudrate 115200 \
  --mode echo
```

PC 应收到：

```text
RDK_READY
```

PC 发送 `hello`，RDK 终端会同时打印接收的 HEX 和文本，并把完全相同的字节发回 PC。PC 使用十六进制发送 `01 A5 7F` 时，也应原样收到 `01 A5 7F`。这一步通过表示 TX、RX、GND、波特率和双向收发均正常。

按 `Ctrl+C` 停止 RDK 工具。

### 10.3 第二步：连续 18 字节视觉包测试

先确保该串口连接的是 PC 测试端，而不是已使能电机的控制器，然后运行：

```bash
python3 -m project.Tools.serial_duplex_test \
  --serial-port /dev/ttyS1 \
  --baudrate 115200 \
  --mode packet \
  --interval 0.5
```

PC 串口助手切换为 HEX 接收，应每 0.5 秒收到一个以 `A5 20` 开头的 18 字节包。测试值固定为：

```text
error_cm = -2.0
position_cm = +3.0
velocity_cm_s = -2.0
sequence = 每包递增
```

因为序号变化，最后的 CRC 也会随每包变化。PC 以 ASCII 发送 `PING` 时，RDK 会额外回复 `PONG\r\n`，用于确认 packet 模式下反向链路仍然正常。

`echo` 和 `packet` 都是联调工具。正式运行 `run_vision_serial` 时，上位机只发送视觉二进制帧，不处理 `PING` 或回显字符，避免测试数据进入电机控制链路。
