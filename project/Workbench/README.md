# H题滚球视觉教学与仿真实验台

## 1. 这是什么

这是为《H题：车载平衡滚球运动控制系统》视觉部分制作的浏览器上位机，也是一个可以实时操作的教学与仿真平台。

它不只是显示摄像头画面，而是把视觉流程从头到尾拆成可以观察和操作的步骤：

1. 建立导轨、钢球、相机和相机视锥的三维模型。
2. 在已知厘米位置放置钢球，采集对应的像素坐标。
3. 根据标定点建立像素坐标到物理坐标的映射。
4. 比较线性映射、射影映射和二维单应性变换的效果。
5. 通过二维受力图理解重力、支持力、摩擦力、惯性力和加速度关系。
6. 查看映射误差、RMSE、最大误差和实时测量结果。
7. 运行钢球闭环控制仿真，观察目标位置、扰动和响应曲线。

当前版本使用虚拟相机和仿真数据，不会访问真实的 `/dev/video*` 摄像头。后续可以接入工程中已经完成畸变矫正的 Python 相机程序。

视觉反馈、PID、车辆加速度前馈和舵机之间的完整控制关系，见 [`H题滚球控制系统架构.md`](../../H题滚球控制系统架构.md)。

## 2. 当前已经实现的功能

### 2.1 三维实验模型

- 25 cm 导轨、V形槽、钢球和毫米级刻度。
- 中心零点标记和标定点标记。
- 虚拟相机机身和相机视锥。
- 鼠标旋转、滚轮缩放和钢球拖动。
- 透视、俯视和侧面三种预设视角。

### 2.2 虚拟相机

- 固定输出 `640×480` 像素坐标。
- 相机数据源按题目工程统一标记为 `120 FPS`。
- 可调整安装高度、斜视角度和垂直视场角 FOV。
- 可调整径向畸变系数 `k1` 和像素测量噪声。
- 实时显示钢球在虚拟图像中的 `(u, v)` 像素坐标。
- 虚拟相机窗口标记为 `UNDISTORTED`，表示平台默认按矫正后的图像坐标进行后续标定和映射。

`120 FPS` 表示视觉数据采集频率。上位机画面限制为约 30 Hz 刷新，以便给真实视觉算法和板端系统留下 CPU/GPU 余量。

### 2.3 标定与映射

- 在已知真实位置采集 `(x_cm, u, v)` 标定样本。
- 默认生成 `-10、-5、0、+5、+10 cm` 五个标定点。
- 支持增加、删除和重建标定点。
- 支持一维线性映射。
- 支持一维射影映射。
- 支持四点二维单应性变换。
- 显示模型公式、RMSE、最大误差和当前绝对误差。

### 2.4 二维受力分析

- 用高中物理受力图显示重力 `mg`、支持力 `N` 和静摩擦力 `f`。
- 显示小车加速度、钢球水平加速度和随车系惯性力。
- 支持“地面惯性系”和“随车非惯性系”切换。
- 调整小车加速度、导轨角度和钢球质量后实时重新计算。
- 一键应用理论平衡角，验证 `a相对≈0` 和 `a球,x≈a车`。

### 2.5 动态仿真

- 设置钢球目标位置。
- 调整 `Kp、Ki、Kd`。
- 设置小车沿导轨方向的加速度。
- 打开或关闭加速度前馈，直接比较两种控制效果。
- 显示反馈角、前馈角、舵机指令角和实际导轨角。
- 使用实心钢球滚动惯量和一阶舵机响应，而不是简单的质点模型。
- 启动、暂停和重置闭环仿真。
- 施加瞬时速度扰动。
- 实时显示钢球位置、导轨倾角和位置响应曲线。

## 3. 界面的五个教学阶段

### STEP 01：系统总览

这一阶段用于理解整个视觉系统的空间关系。

可以观察：

- 钢球在导轨上的真实厘米位置。
- 相机安装高度和倾斜角度。
- 相机视锥覆盖的范围。
- 钢球真实位置如何投影成像素坐标。
- 畸变、FOV 和测量噪声如何影响图像结果。

建议先拖动钢球，再调整相机参数，观察左下角虚拟相机画面和底部像素坐标如何变化。

### STEP 02：几何标定

这一阶段模拟真实标定过程。

操作步骤：

1. 将钢球移动到一个已知刻度位置。
2. 点击“采集当前位置”。
3. 系统记录真实位置 `x_cm` 和图像坐标 `(u, v)`。
4. 重复移动和采集，得到多组标定样本。
5. 在标定表中检查样本分布是否覆盖导轨两端和中心。

真实设备上也是同样的思路，只是像素坐标不再由虚拟相机计算，而是由 OpenCV 钢球检测算法给出。

### STEP 03：映射验证

这一阶段把像素坐标转换成导轨上的厘米位置。

可以切换三种模型：

- `线性`：使用 `x = au + b`，适合相机接近垂直俯视且透视影响较小时。
- `射影`：使用一维分式模型，适合导轨方向存在明显透视压缩时。
- `单应性`：使用二维平面透视变换，同时利用像素 `u、v`，适合相机斜视平面目标。

判断模型是否合适时，不只看公式，还要看：

- RMSE 是否足够小。
- 最大误差是否满足题目要求。
- 导轨两端的误差是否明显大于中心误差。
- 改变相机角度后，原标定参数是否仍然有效。

### STEP 04：受力建模

这一阶段用二维平面图解释车载滚球系统的控制目的和公式来源。

可以切换两个参考系：

- `地面惯性系`：只画真实力，并用 `F=ma` 分析钢球在地面中的加速度。
- `随车非惯性系`：增加反向惯性力 `-ma车`，直接分析钢球相对小车的运动。

建议先设置小车加速度，再任意改变导轨角度，观察钢球会相对小车向前还是向后滚；最后点击“应用理论平衡角”，验证相对加速度接近零。

### STEP 05：动态仿真

这一阶段用于理解视觉测量进入闭环控制后的效果。

操作步骤：

1. 输入目标位置，例如 `5 cm`。
2. 设置小车加速度，例如 `+1.0 m/s²`。
3. 打开或关闭“加速度前馈”。
4. 点击“运行”。
5. 观察钢球、导轨倾角、各控制角度和位置响应曲线。
6. 点击闪电图标施加扰动。
7. 调整 `Kp、Ki、Kd`，比较响应速度、超调和稳定性。

这里的控制器主要用于教学演示，不应直接替代最终下位机控制算法。

- 3D WebGL 画布是否真正绘制出内容。
- 四个教学阶段是否可以切换。

## 13. 车载滚球物理模型与加速度前馈

### 13.1 为什么只看普通 PID 不够

导轨安装在运动小车上。当小车向前加速时，钢球因为惯性会相对小车向后运动。即使此时导轨完全水平、钢球原来位于目标点，也会出现位置偏差。

普通位置 PID 只能在检测到偏差后再调整导轨：

```text
小车开始加速
    ↓
钢球因为惯性向后偏移
    ↓
视觉检测到位置误差
    ↓
PID 产生导轨角度
    ↓
钢球回到目标点
```

带积分项的 PID 最终能够抵消近似恒定的小车加速度，但它必须先积累误差。在车辆频繁加速、减速和转弯时，这种滞后会造成更大的瞬时偏差，也更容易让舵机角度饱和。

前馈控制利用已经知道或估计到的小车加速度，在钢球明显偏移前就给出一个理论补偿角：

```text
小车加速度
    ├──> 理论前馈角
    └──> 钢球位置扰动

位置误差 ──> PID反馈角

舵机指令角 = 前馈角 + PID反馈角
```

因此不是“PID 完全不能控制”，而是“前馈负责提前抵消可测扰动，PID 负责修正剩余误差”。

### 13.2 坐标和符号约定

- `x`：钢球相对导轨中心的位置，向小车前进方向为正，单位在界面中为 cm。
- `a_car`：小车沿导轨正方向的加速度，单位为 `m/s²`。
- `θ`：导轨角度；正角度表示导轨 `+x` 一端降低，使重力推动钢球向 `+x` 方向滚动。
- `g`：重力加速度，模型采用 `9.80665 m/s²`。
- `c`：等效滚动阻尼系数。

当前模型假设导轨方向与小车纵向一致。更一般的情况下，应使用车体加速度在导轨方向上的投影：

```text
a_parallel = a_vehicle · e_rod
```

### 13.3 实心钢球的滚动方程

钢球不是沿斜面滑动的质点，它还会转动。纯滚动条件下：

```text
I = 2/5 mR²
```

在随小车加速的非惯性坐标系中，沿导轨方向的模型为：

```text
              g sinθ - a_car cosθ
x_ddot =  -----------------------------  - c x_dot
                  1 + I/(mR²)
```

代入实心球转动惯量后：

```text
x_ddot = 5/7 [g sinθ - a_car cosθ] - c x_dot
```

这里质量 `m` 和半径 `R` 在理想纯滚动模型中约掉了，所以改变钢球质量不会直接改变理想加速度。但在真实机构中，接触变形、槽形、滚动阻力和打滑仍会让不同钢球表现不同。

### 13.4 加速度前馈角

希望钢球相对导轨保持不动，就令理论相对加速度为零：

```text
g sinθ_ff - a_car cosθ_ff = 0
```

得到：

```text
θ_ff = atan(a_car / g)
```

例如小车向前加速度为 `1.0 m/s²`：

```text
θ_ff = atan(1.0 / 9.80665) ≈ 5.82°
```

最终角度指令为：

```text
θ_cmd = clamp(θ_PID + θ_ff, -12°, +12°)
```

其中：

```text
θ_PID = Kp(x_target - x) + Ki∫(x_target - x)dt - Kd x_dot
```

Workbench 还使用时间常数约 `90 ms` 的一阶环节模拟舵机响应，因此实际导轨角不会瞬间等于指令角。

### 13.5 小车加速度和钢球加速度怎么算

先区分三个不同的加速度：

```text
a_car       小车相对地面的加速度
a_relative  钢球相对导轨的加速度
a_ball      钢球相对地面的加速度
```

小车加速度可以用高中运动学中的速度变化率计算：

```text
a_car ≈ (v_car[k] - v_car[k-1]) / Δt
```

如果一段时间内近似匀加速，也可以使用：

```text
v = v0 + a_car t
s = v0 t + 1/2 a_car t²
```

真实小车中，`v_car` 可以来自轮速编码器；也可以使用经过姿态和重力补偿的 IMU 加速度。

钢球相对导轨的位置 `x_relative` 由摄像头检测并映射成厘米坐标。理论上可以差分得到：

```text
v_relative ≈ (x[k] - x[k-1]) / Δt
a_relative ≈ (v[k] - v[k-1]) / Δt
```

但位置连续差分两次会严重放大视觉噪声，真实系统应使用 α-β 滤波或卡尔曼滤波估计速度，不建议把二次差分结果直接送入控制器。

在当前“导轨角度变化较慢”的简化模型中，钢球相对地面的水平加速度为：

```text
a_ball,x = a_car + a_relative cosθ
```

竖直方向为：

```text
a_ball,y = -a_relative sinθ
```

因此，当钢球稳定保持在车上的目标点时：

```text
x_relative = x_target
v_relative = 0
a_relative = 0
```

于是得到：

```text
a_ball,x = a_car
```

这就是“球的加速度与车的加速度一致”的准确含义：它是钢球相对小车不再移动时，在地面惯性系中的结果，不是控制器每一瞬间都强行令两个测量值相等。

在过渡过程中，控制器需要允许 `a_relative` 不为零，才能让已经偏离目标点的钢球滚回去。例如钢球落后于目标点时，导轨应产生指向目标点的相对加速度。

二维受力图还计算：

```text
N = m(g cosθ + a_car sinθ)
f = -(I/R²)a_relative
```

对于实心球：

```text
f = -2/5 m a_relative
```

质量会影响 `mg、N、f` 等力的大小，但在理想纯滚动方程中会约掉，所以不会直接改变理论滚动加速度。

### 13.6 在界面中如何比较

1. 进入“动态仿真”。
2. 将目标位置设为 `0 cm`。
3. 将小车加速度设为 `+1.0 m/s²`。
4. 关闭加速度前馈并运行，观察钢球先向负方向偏移，PID 再进行修正。
5. 重置仿真，打开加速度前馈后再次运行。
6. 比较位置曲线、最大偏差、反馈角和前馈角。
7. 把小车加速度改成负值，检查补偿角和钢球运动方向是否同时反向。

右侧物理模型读数含义：

- `反馈角 θPID`：由钢球位置误差和速度产生的纠偏角。
- `前馈角 θFF`：根据小车加速度直接计算的理论平衡角。
- `舵机指令 θ*`：前馈与反馈相加并经过角度限幅后的结果。
- `实际导轨角`：加入舵机响应延迟后的真实角度。
- `钢球速度`：钢球相对导轨的速度。
- `钢球加速度`：滚动惯量、重力、小车惯性力和阻尼共同作用的结果。

### 13.7 真实系统如何获得小车加速度

前馈量可以来自：

- 小车控制器已经生成的速度规划或电机加速度指令。
- 编码器速度差分后经过低通滤波得到的加速度。
- IMU 测量值经过零偏、姿态和重力补偿后的纵向加速度。
- 上述信号的融合结果。

不能把 IMU 原始某一轴数据直接代入公式。加速度计测到的是比力，包含安装角误差、重力投影、振动和零偏；如果不做姿态补偿和滤波，前馈反而会把噪声直接送到舵机。

真实系统建议先从较小的前馈比例开始：

```text
θ_cmd = θ_PID + Kff · atan(a_car / g)
```

将 `Kff` 从 `0` 逐步增加到接近 `1`，通过实车加速和减速实验验证方向、比例、延迟和限幅。Workbench 当前使用理想的 `Kff = 1`，用于展示理论效果。

### 13.8 当前模型没有包含什么

为了保持教学模型清晰，当前暂未包含：

- 导轨快速转动产生的角加速度、科里奥利力和离心力项。
- V形槽两侧接触导致的等效转动惯量变化。
- 钢球打滑、碰撞、导轨不平和干摩擦死区。
- 舵机回差、PWM 死区、电源波动和结构柔性。
- 视觉处理延迟、串口延迟和丢帧。
- 车辆转弯时横向加速度在导轨方向上的投影误差。

这些因素后续可以逐项加入，但应先通过真实实验辨识参数，否则增加复杂度并不会自动提高模型准确度。
