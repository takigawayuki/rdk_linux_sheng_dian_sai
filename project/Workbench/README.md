# H题滚球视觉教学与仿真实验台

## 1. 这是什么

这是为《H题：车载平衡滚球运动控制系统》视觉部分制作的浏览器上位机，也是一个可以实时操作的教学与仿真平台。

它不只是显示摄像头画面，而是把视觉流程从头到尾拆成可以观察和操作的步骤：

1. 建立导轨、钢球、相机和相机视锥的三维模型。
2. 在已知厘米位置放置钢球，采集对应的像素坐标。
3. 根据标定点建立像素坐标到物理坐标的映射。
4. 比较线性映射、射影映射和二维单应性变换的效果。
5. 查看映射误差、RMSE、最大误差和实时测量结果。
6. 运行钢球闭环控制仿真，观察目标位置、扰动和响应曲线。

当前版本使用虚拟相机和仿真数据，不会访问真实的 `/dev/video*` 摄像头。后续可以接入工程中已经完成畸变矫正的 Python 相机程序。

## 2. 当前已经实现的功能

### 2.1 三维实验模型

- 25 cm 导轨、V形槽、钢球和毫米级刻度。
- 中心零点标记和标定点标记。
- 虚拟相机机身和相机视锥。
- 鼠标旋转、滚轮缩放和钢球拖动。
- 透视、俯视和侧面三种预设视角。

### 2.2 虚拟相机

- 固定输出 `640×480` 像素坐标。
- 相机数据源按题目工程统一标记为 `120 FPS`。
- 可调整安装高度、斜视角度和垂直视场角 FOV。
- 可调整径向畸变系数 `k1` 和像素测量噪声。
- 实时显示钢球在虚拟图像中的 `(u, v)` 像素坐标。
- 虚拟相机窗口标记为 `UNDISTORTED`，表示平台默认按矫正后的图像坐标进行后续标定和映射。

`120 FPS` 表示视觉数据采集频率。上位机画面限制为约 30 Hz 刷新，以便给真实视觉算法和板端系统留下 CPU/GPU 余量。

### 2.3 标定与映射

- 在已知真实位置采集 `(x_cm, u, v)` 标定样本。
- 默认生成 `-10、-5、0、+5、+10 cm` 五个标定点。
- 支持增加、删除和重建标定点。
- 支持一维线性映射。
- 支持一维射影映射。
- 支持四点二维单应性变换。
- 显示模型公式、RMSE、最大误差和当前绝对误差。

### 2.4 动态仿真

- 设置钢球目标位置。
- 调整 `Kp` 和 `Kd`。
- 启动、暂停和重置闭环仿真。
- 施加瞬时速度扰动。
- 实时显示钢球位置、导轨倾角和位置响应曲线。

## 3. 界面的四个教学阶段

### STEP 01：系统总览

这一阶段用于理解整个视觉系统的空间关系。

可以观察：

- 钢球在导轨上的真实厘米位置。
- 相机安装高度和倾斜角度。
- 相机视锥覆盖的范围。
- 钢球真实位置如何投影成像素坐标。
- 畸变、FOV 和测量噪声如何影响图像结果。

建议先拖动钢球，再调整相机参数，观察左下角虚拟相机画面和底部像素坐标如何变化。

### STEP 02：几何标定

这一阶段模拟真实标定过程。

操作步骤：

1. 将钢球移动到一个已知刻度位置。
2. 点击“采集当前位置”。
3. 系统记录真实位置 `x_cm` 和图像坐标 `(u, v)`。
4. 重复移动和采集，得到多组标定样本。
5. 在标定表中检查样本分布是否覆盖导轨两端和中心。

真实设备上也是同样的思路，只是像素坐标不再由虚拟相机计算，而是由 OpenCV 钢球检测算法给出。

### STEP 03：映射验证

这一阶段把像素坐标转换成导轨上的厘米位置。

可以切换三种模型：

- `线性`：使用 `x = au + b`，适合相机接近垂直俯视且透视影响较小时。
- `射影`：使用一维分式模型，适合导轨方向存在明显透视压缩时。
- `单应性`：使用二维平面透视变换，同时利用像素 `u、v`，适合相机斜视平面目标。

判断模型是否合适时，不只看公式，还要看：

- RMSE 是否足够小。
- 最大误差是否满足题目要求。
- 导轨两端的误差是否明显大于中心误差。
- 改变相机角度后，原标定参数是否仍然有效。

### STEP 04：动态仿真

这一阶段用于理解视觉测量进入闭环控制后的效果。

操作步骤：

1. 输入目标位置，例如 `5 cm`。
2. 点击“运行”。
3. 观察钢球、导轨倾角和位置响应曲线。
4. 点击闪电图标施加扰动。
5. 调整 `Kp、Kd`，比较响应速度、超调和稳定性。

这里的控制器主要用于教学演示，不应直接替代最终下位机控制算法。


```text
http://localhost:4173/

```

## 5. 常用命令是什么意思

### `npm install`

读取 `package.json` 并安装 Three.js、Vite、TypeScript、Lucide 和 Playwright 等依赖。通常只需第一次运行或依赖更新后执行。

### `npm run dev`

启动开发服务器。修改 `src/` 中的代码后，浏览器会自动刷新，适合开发和调试。

### `npm run build`

先检查 TypeScript 类型，再生成优化后的生产文件到 `dist/`。它用于确认代码能否正确发布，不会启动网页服务器。

### `npm run preview`

启动一个本地服务器预览 `dist/` 中的生产构建。执行前应先运行 `npm run build`。

### `npm run test:e2e`

使用 Playwright 自动检查桌面端和移动端界面，包括：

- 3D WebGL 画布是否真正绘制出内容。
- 四个教学阶段是否可以切换。
- 标定点是否可以采集。
- 映射模型是否可以切换和计算。
- 动态仿真是否会改变钢球位置。
- 三维场景和参数面板是否发生重叠。

在 RDK 开发板上，完整测试可能耗时较长，因为无头浏览器通常使用软件 WebGL。

## 6. 鼠标和界面操作

- 拖动三维画布空白区域：旋转观察视角。
- 鼠标滚轮：缩放三维视角。
- 直接拖动三维钢球：改变钢球位置。
- 拖动“钢球位置”滑块：精确改变位置。
- 点击右上角三个视角图标：切换透视、俯视和侧面视角。
- 点击“采集当前位置”：增加一个标定样本。
- 点击刷新图标：按当前相机参数重建默认标定点。
- 点击标定表中的 `×`：删除对应标定点。
- 点击闪电图标：给动态仿真施加扰动。

手机界面会把三维场景放在上方、参数面板放在下方，左侧步骤栏仍然保留。

## 8. 各代码文件负责什么

### `src/main.ts`

负责生成整个上位机页面，管理四个阶段、读取控件参数、保存标定样本、更新虚拟相机画面、曲线和底部遥测数据。

### `src/scene.ts`

负责 Three.js 三维场景，包括导轨、刻度、钢球、相机模型、相机视锥、灯光、视角控制和钢球拖动。它还包含虚拟相机的三维点投影逻辑。

### `src/math.ts`

负责视觉坐标映射的数学计算，包括：

- 最小二乘线性拟合。
- 一维射影拟合。
- 四点单应性矩阵计算。
- RMSE、最大误差和逐点残差。

### `src/simulation.ts`

负责钢球位置、速度、导轨倾角、目标值和扰动的动态更新。目前使用适合教学展示的简化动力学与 PD 控制逻辑。

### `src/styles.css`

负责工作台布局、控件尺寸、颜色、三维场景叠加窗口以及桌面端和手机端适配。

## 9. 和 Python 视觉工程的关系

Workbench 当前是独立前端，不直接修改下面这些 Python 模块：

```text
project/Driver/camera.py
project/Driver/calibration/undistorter.py
project/Tools/collect_samples.py
project/Algorithm/
```

这些 Python 模块负责真实相机采集、畸变矫正、样本保存和后续视觉算法；Workbench 负责教学展示、交互操作、曲线和三维仿真。

真实系统推荐的数据流是：

```text
原始摄像头
    ↓
Driver/camera.py
    ↓
Undistorter 畸变矫正
    ↓
钢球检测，得到像素坐标 (u, v)
    ↓
标定映射，得到物理位置 x_cm
    ↓
Python 实时数据服务
    ↓
Workbench 上位机显示
```

## 10. 后续接入真实摄像头需要的数据

前端建议从 Python 服务接收下面的数据：

```text
timestamp             时间戳
frame_url             实时画面或视频流地址
pixel_x, pixel_y      检测到的钢球像素坐标
position_cm           映射后的实际位置
velocity_cm_s         估计速度
confidence            检测置信度
detected              当前帧是否检测成功
predicted             是否使用滤波预测值
target_cm             控制目标位置
rod_angle_deg         当前导轨角度
```

接入时建议新增数据源适配模块，例如：

```text
src/data/
├── types.ts           # 前后端数据结构
├── simulation.ts      # 当前虚拟数据源
└── websocket.ts       # Python WebSocket 真实数据源
```

这样只需要切换数据源，不需要重写三维场景、映射数学和界面控件。

## 11. 当前边界

- 当前显示的是仿真画面，不是 `/dev/video*` 的真实视频流。
- 当前 `UNDISTORTED` 表示仿真流程采用矫正后的坐标约定，不代表页面正在调用 Python 畸变矫正器。
- 当前单应性使用虚拟导轨四角点计算，真实比赛时必须换成实际采集的图像点和物理点。
- 当前动态模型用于理解闭环过程，最终控制参数必须在真实机械结构上重新调试。
- 改变真实相机位置、焦距或分辨率后，需要重新标定。
